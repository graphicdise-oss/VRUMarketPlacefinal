# ขึ้นระบบจริงบนเครื่องของมหาวิทยาลัย — §99

**ไฟล์ในโฟลเดอร์นี้ + `docker-compose.yml` ที่ root คือทั้งหมดที่เครื่องจริงต้องใช้** · ทดลองรันครบทั้งชุด
(build image → migrate บนฐานข้อมูลเปล่า → API → Nginx ด่านหน้า) แล้ว 2026-09-29 ผลอยู่ท้ายไฟล์

ระบบรันเป็น**อินสแตนซ์เดียวโดยตั้งใจ** (cron · แชท · ไฟล์อัปโหลด · ตัวนับ rate limit ผูกกับโปรเซสเดียว)
— ไม่ต้องมี Redis, load balancer หรือ object storage

## ต้องรู้จากไอทีก่อนเริ่ม

รายการคำถามเต็มพร้อมเหตุผลอยู่ใน artifact ที่ส่งให้เจ้าของโปรเจค · สามข้อที่กระทบไฟล์ในนี้โดยตรง:

| คำถาม | กระทบอะไร |
|---|---|
| หน้าเครื่องมี proxy / load balancer / WAF ของมหาวิทยาลัยกี่ชั้น และส่ง `X-Forwarded-For` ต่อไหม | `TRUST_PROXY_HOPS` ใน `.env` — Nginx ของเราตัวเดียว = `1` · มีอีกชั้นที่ต่อท้าย header ด้วย = `2` · **ตั้งผิดแล้ว rate limit นับทุกคนเป็นคนเดียว หรือให้คนปลอม IP ตัวเองได้ และ log ตาม ม.26 ได้ IP ผิด** |
| **อีเมล**: ใช้ระบบอีเมลของมหาวิทยาลัยได้ไหม (Google Workspace / Microsoft 365 / เซิร์ฟเวอร์เอง) · สร้างบัญชีของระบบ (`noreply@...`) ที่ส่งผ่าน SMTP ได้ไหม · ส่งได้วันละกี่ฉบับ · เครื่องออกไปพอร์ต SMTP ได้ไหม | ได้ → `EMAIL_TRANSPORT=smtp` + `SMTP_HOST` `SMTP_PORT` `SMTP_USER` `SMTP_PASSWORD` · ไม่ได้ → `EMAIL_TRANSPORT=brevo` + `BREVO_API_KEY` (§107) · **SMTP ต้องมี TLS** (587 STARTTLS หรือ 465) — เซิร์ฟเวอร์ที่ไม่มี TLS ระบบจะไม่ส่งรหัสผ่านไปให้ · Microsoft 365 มักปิด SMTP AUTH ไว้ ต้องให้ IT เปิดให้บัญชีนี้ |
| เครื่องมีแรมเท่าไหร่ | `API_MEMORY_LIMIT` (ตั้งต้น 1g) · `POSTGRES_MEMORY_LIMIT` (ตั้งต้น 512m) — **เครื่องควรมีอย่างน้อย 2GB** ดูตัวเลขที่วัดได้ด้านล่าง |
| โดเมนอะไร ใครออกใบรับรอง HTTPS | `server_name` และ `ssl_certificate` ใน `nginx-site.conf` · `FRONTEND_BASE_URL` และ `GOOGLE_REDIRECT_URI` ใน `.env` · **ต้องเป็น HTTPS** เพราะ cookie ล็อกอินเป็น `Secure` ในโหมด production — ผ่าน http ธรรมดาจะไม่มีใครล็อกอินได้เลย |

## ขั้นตอน

```bash
# 1. โค้ด
git clone <repo> /opt/vru-marketplace && cd /opt/vru-marketplace

# 2. ความลับ — สร้างใหม่ทุกตัว ห้ามใช้ค่าจากเครื่องอื่น
cp .env.example .env
openssl rand -hex 32     # รันหนึ่งครั้งต่อหนึ่งตัวแปรที่มีคำว่า replace-me แล้วแปะลง .env
```

แก้ `.env` ให้ครบ:

- **ทุกบรรทัดที่มี `replace-me`** — ถ้าเหลือแม้แต่ตัวเดียว **API จะไม่ยอมบูต** และบอกชื่อตัวแปรที่ค้าง
  (§99 · ดูได้ด้วย `docker compose logs api`) · `POSTGRES_PASSWORD` ที่ยังเป็นค่าตัวอย่าง **Postgres ไม่ยอมเริ่ม
  ตั้งแต่แรก** (`docker compose logs postgres`) — ฐานข้อมูลจึงไม่มีทางถูกสร้างด้วยรหัสผ่านที่อยู่ในไฟล์สาธารณะ · ค่าจริงของ Brevo และ Google เอามาจากหน้า console ของแต่ละเจ้า
- **`ACCOUNT_MARKER_PEPPER` เปลี่ยนไม่ได้อีกเลยหลังเปิดระบบ** — เก็บสำเนาไว้ที่ปลอดภัยนอกเครื่อง
  ถ้าหายหรือเปลี่ยน คนที่เคยถูกแบนทุกคนสมัครใหม่ได้ทันที (K16)
- `POSTGRES_PASSWORD` — ใช้ค่า hex จาก `openssl rand -hex 32` เท่านั้น (มันถูกประกอบเข้าไปใน URL)
- `FRONTEND_BASE_URL=https://<โดเมนจริง>` · `GOOGLE_REDIRECT_URI=https://<โดเมนจริง>/api/v1/auth/google/callback`
  (ลงทะเบียน URI นี้ใน Google Cloud Console ให้ตรงทุกตัวอักษร)
- `TRUST_PROXY_HOPS` ตามคำตอบของไอที

```bash
# 3. ระบบ — build, migrate บนฐานข้อมูลเปล่า, สตาร์ต API
docker compose up -d --build
docker compose ps          # migrate = Exited (0) · api / postgres = healthy
curl http://127.0.0.1:3000/api/v1/health

# 4. Nginx — ติดตั้งบนเครื่องเดียวกัน
sudo cp ops/deploy/nginx-site.conf /etc/nginx/sites-available/vru-marketplace
sudo ln -s /etc/nginx/sites-available/vru-marketplace /etc/nginx/sites-enabled/
sudoedit /etc/nginx/sites-available/vru-marketplace     # แก้สามจุดที่เขียนว่า CHANGE ME
sudo nginx -t && sudo systemctl reload nginx

# 5. backup — ตาม ops/backup/README.md (issue #21) · ต้องทำก่อนเปิดให้คนใช้
```

**ห้ามใช้ `docker-compose.dev.yml` บนเครื่องจริง** — ไฟล์นั้นเปิดพอร์ตฐานข้อมูลออกมาที่ host สำหรับรันเทสต์
บนเครื่องพัฒนา · `docker compose` เปล่าๆ ไม่โหลดมันเอง (ตั้งใจไม่ใช้ชื่อ `docker-compose.override.yml`
ซึ่ง compose โหลดอัตโนมัติ)

## อะไรปิดไว้บ้าง และทำไม

| | เครื่องพัฒนาแบบเดิม (ก่อน §99) | ตอนนี้ |
|---|---|---|
| PostgreSQL | เปิด `0.0.0.0:5432` รหัสผ่าน `postgres` — **เข้าได้จากเครือข่าย** (ลองแล้ว) | ไม่เปิดพอร์ตเลย เข้าได้จากใน compose เท่านั้น · ไม่มีรหัสผ่านตั้งต้น ไม่ใส่ = compose ไม่ยอมรัน |
| API | `0.0.0.0:3000` — ประตูที่สองที่ไม่ผ่าน Nginx | `127.0.0.1:3000` — ทางเข้าเดียวคือ Nginx บนเครื่องเดียวกัน |
| ความลับค่าตัวอย่าง | บูตได้ปกติ — ใครอ่าน `.env.example` ก็ปลอม cookie ล็อกอินได้ | API ไม่บูต บอกชื่อตัวแปรที่ยังเป็นค่าตัวอย่าง · รหัสฐานข้อมูลค่าตัวอย่าง = Postgres ไม่เริ่ม |
| พอร์ต API | ตาม `PORT` ใน `.env` | ตรึง `127.0.0.1:3000` คู่กับ `upstream` ใน `nginx-site.conf` — เปลี่ยนต้องแก้ทั้งสองไฟล์ |
| log ของ Docker | ไม่มีเพดาน ดิสก์เต็มได้สักวัน | 5 ไฟล์ × 10MB ต่อ container |
| หน่วยความจำ | ไม่มีเพดาน | API 1g · PostgreSQL 512m (ปรับใน `.env`) |

⚠️ Docker เปิดพอร์ตที่ publish **อ้อม firewall ของ host** (ufw / iptables ไม่เห็น) — เหตุผลที่ต้องไม่ publish
ฐานข้อมูลเลย แทนที่จะพึ่ง firewall

## ตัวเลขหน่วยความจำที่วัดได้ (2026-09-29)

วัดจาก container `api` จริง ส่งหลักฐานข้อพิพาทเต็มเพดาน (10 รูป × ~9.85MB) ผ่าน Nginx:

| สถานการณ์ | ตั้งค่าเดิมของ glibc | `MALLOC_ARENA_MAX=2` (ที่ใช้อยู่) |
|---|---|---|
| ว่าง | ~230MiB | ~245MiB |
| ข้อพิพาทเต็มเพดาน 1 รายการ | สูงสุด ~500MiB · ค้างหลังจบ 502MiB | สูงสุด ~445MiB · ค้างหลังจบ 383MiB |
| 2 รายการพร้อมกัน | ~800MiB | ~700MiB |

`MALLOC_ARENA_MAX=2` ลดหน่วยความจำที่ sharp (ตัว re-encode รูป) ค้างไว้หลังงานจบ — ตามที่เอกสารของ sharp
แนะนำสำหรับ glibc

**การยิงอัปโหลดพร้อมกันจำนวนมาก — แก้แล้วใน §100** (เจอตอนทดสอบ §99: บัญชีใหม่ยิง 12 คำขอพร้อมกันไปออเดอร์ปลอม
→ API ถูก kernel ฆ่า) · ตอนนี้ไฟล์รอบนดิสก์ไม่ใช่หน่วยความจำ · แปลงรูปพร้อมกันได้ 2 งาน (`IMAGE_PROCESSING_CONCURRENCY`)
ที่เกินรอคิว ≤ 20 วินาทีแล้วได้ 503 · อัปโหลดได้ 60 ครั้ง/ชั่วโมง/บัญชี (`RATE_LIMIT_UPLOAD_PER_HOUR`) · และตรวจสิทธิ์ก่อนอ่านไฟล์ ·
วัดซ้ำ: 24 คำขอไปออเดอร์ปลอม = 404 ทั้งหมด หน่วยความจำไม่ขยับ · ข้อพิพาทจริงเต็มเพดาน 10 รายการพร้อมกัน = สำเร็จทุกใบ
หน่วยความจำของโปรเซสสูงสุด 508MiB · **ถ้าจะเพิ่ม `IMAGE_PROCESSING_CONCURRENCY` ต้องเพิ่ม `API_MEMORY_LIMIT` ตาม** (ราว 200MiB ต่อช่อง)

ไฟล์ชั่วคราวของอัปโหลดอยู่ใน `/tmp` ของ container (`UPLOAD_TMP_DIR`) · ลบเองเมื่อคำขอจบ · ไม่ต้อง backup

## Nginx

`nginx-site.conf` ทดสอบกับ Nginx 1.24 (Ubuntu 24.04) และ 1.27 แล้ว — 1.27 เตือนว่า `listen ... http2`
เลิกแนะนำแล้ว เป็นแค่คำเตือน ใช้งานได้

- **ขนาด body** — 110MB เฉพาะสองเส้นของหลักฐานข้อพิพาท · 11MB ที่เหลือทั้งหมด · เกินแล้ว Nginx ตอบ 413
  เป็น JSON รูปแบบเดียวกับ error ของ API (`PAYLOAD_TOO_LARGE`)
- **Nginx พักไฟล์อัปโหลดลงดิสก์ก่อนส่งต่อ** (`/var/lib/nginx/body` ของ Ubuntu) — ต้องมีที่ว่างพอสำหรับ
  อัปโหลดพร้อมกันหลายรายการ (สูงสุด ~110MB ต่อรายการ) และ user ของ worker ต้องเขียนได้ ไม่งั้นได้ 500
  โดยที่ API ไม่เห็นคำขอเลย (เจอจริงตอนทดสอบ)
- **แชท** ต้องผ่าน WebSocket ที่ `/api/v1/socket.io/` · ถ้า header `Upgrade` ไม่ถึง API แชทยังใช้ได้
  แต่ตกไปใช้ long-polling เงียบๆ
- **IPv6** — ไม่ได้ `listen [::]` ไว้ เพราะเครื่องที่ปิด IPv6 จะทำให้ Nginx ไม่ยอมสตาร์ต (เจอจริงตอนทดสอบ)
  ถ้าไอทีบอกว่ามี IPv6 ให้เพิ่มเอง
- **หน้าบ้าน** เสิร์ฟจากโฟลเดอร์ใน `location /` (repo หน้าบ้านเป็นคนสร้างไฟล์) · ถ้ายังไม่มี `index.html`
  ทุกเส้นทางของหน้าบ้านจะได้ 500

## เปลี่ยนรหัสผ่านฐานข้อมูลหลังเปิดระบบ

PostgreSQL อ่าน `POSTGRES_PASSWORD` **ครั้งเดียวตอนสร้าง volume ครั้งแรก** — แก้ `.env` อย่างเดียวไม่เปลี่ยน
รหัสผ่านจริง แต่ API จะต่อไม่ติด:

```bash
docker compose exec postgres psql -U postgres -c "ALTER USER postgres PASSWORD '<ค่าใหม่>'"
# แล้วแก้ POSTGRES_PASSWORD ใน .env ให้ตรง
docker compose up -d
```

## ผลการทดลองรันครบชุด (2026-09-29)

รันบนเครื่องของ agent ด้วย Docker 29 + Compose 5 · image ดึงผ่าน `mirror.gcr.io` (Docker Hub จำกัดการดึง
แบบไม่ล็อกอิน) · Nginx 1.24 บนเครื่องเดียวกันฟังพอร์ต 80/443 จริง ใบรับรอง self-signed ของโดเมนสมมติ

**ความต่างเดียวจากของจริง:** เครือข่ายของเครื่อง agent ถอด TLS กลางทาง ตอน build จึงต้องเติมสองบรรทัดให้
เชื่อ CA ของมัน (ทำในไฟล์นอก repo · `Dockerfile` ใน repo ไม่ได้แตะ) — เครื่องของมหาวิทยาลัยไม่ต้องทำ

**`.env` ที่ก๊อปจาก `.env.example` ตรงๆ:** Postgres ไม่เริ่ม บอกว่า `POSTGRES_PASSWORD` ยังเป็นค่าตัวอย่าง ·
volume ว่าง · migrate และ API ไม่ถูกเริ่ม · (รอบก่อนแก้ตามรีวิว Postgres เริ่มไปแล้ว migrate 54 ใบผ่าน แล้ว API
ปฏิเสธพร้อมชื่อทั้ง 10 ตัวแปร — ช่องที่ปิดคือ volume ถูกสร้างด้วยรหัสสาธารณะ)

**`.env` ค่าจริง (บน volume เดิมจากรอบข้างบน · ใส่ `PORT=4000` ไว้ด้วย) — ผ่าน 14/14 ข้อ ทุกข้อยิงผ่าน
`https://<โดเมน>` เท่านั้น:**
health ผ่าน HTTPS · http → 301 https · เส้นทางของหน้าบ้านได้ `index.html` · เอกสาร API ไม่ถูกเสิร์ฟ ·
ฐานข้อมูลไม่เปิดพอร์ต · API ฟังแค่ loopback · cookie เป็น `Secure; HttpOnly` · log การเข้าใช้เก็บ IP ที่
Nginx เห็น ไม่ใช่ที่ผู้เรียกเขียนมาเอง · แชทต่อเป็น WebSocket จริงและตอบ · แชทที่เงียบไว้ 70 วินาทียังไม่หลุด ·
ข้อพิพาทพร้อมรูปเต็มเพดาน 10 รูป (98.5MB) ผ่าน · API อยู่ใต้เพดานหน่วยความจำ (สูงสุด 443 / 1024MiB) ·
body 12MB ไปเส้นรูปเดียวถูก Nginx ตอบ 413 เป็น JSON · body เกิน 110MB ถูกตอบ 413

**ไฟล์ compose และโค้ดเดิม (ก่อน §99) ด้วย `.env` ที่ก๊อปจาก `.env.example` ตรงๆ:** API บูตด้วยค่าตัวอย่าง · API ตอบจาก IP
เครือข่ายของเครื่องที่ `:3000` · ฐานข้อมูลรับรหัสผ่าน `postgres` จาก IP เครือข่ายของเครื่อง
